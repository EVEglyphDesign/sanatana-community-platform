The offer, in outline

One thing first: a game for the children. Everything else is optional and comes second. Nothing here replaces a volunteer or competes with a supplier the temple already works with.

1 · The educational game

A working game already exists, built for a church community: see the PAIX educational game as it stands today. The engine is finished. Only the content changes — the temple's own stories, festivals and language, chosen by the temple.

PropertyWhat it means
Browser, not an app storeNo download, no install, no accounts of any kind.
A closed worldNo chat, no uploads, no advertisements, no links out. Closed, not moderated.
The body ruleEvery twelve minutes play stops and the child stands and stretches. Not skippable, no penalty, seated alternative available.
Review before renderNothing religious appears until the temple's own reviewers approve it. In doubt the game refuses to render rather than risk getting it wrong.
All the office has to supply is material. Stories, festivals, prayers, language — in whatever form it already exists. Collection is the only ask; the building is not the temple's problem.

2 · The website, only if it is useful

The same approach applied to the web presence: a page set the temple owns outright, with hours, festivals and class times maintained automatically rather than by someone remembering. Entirely optional. A draft already exists: the community page for this temple.

3 · How it is handed over

A fork chain, not a service contract. EVEglyphDesign forks the work to Prasad; Prasad forks it to the temple. Each fork is a complete independent copy. Nothing is rented, nothing expires, and the temple can carry it to any host with or without either of us.

4 · Running it afterwards

Day to day it needs a Perplexity Pro account and GitHub, nothing more. Prasad sits with whoever the temple names and shows them how. Many families in this community already work in IT — this is built deliberately so that they can pick it up and carry it themselves.

5 · If something goes beyond that

Anything larger than Perplexity Pro and a GitHub backend is enterprise work, and it goes to the AI centre of excellence Prasad is part of: custom, open-source, fully sovereign models with no data leaving the temple's control. Small pieces are taken on free as community service. Anything larger comes in well under what a vendor charges to rent a system the temple would never own.

What this is not

  • Not a replacement for anyone already volunteering their time.
  • Not a bid against any supplier or donor already serving the temple.
  • Not a budget request — GitHub Pages serves the surface free.
  • Not permanent — if it is unwelcome it comes down the same day it is asked for.
