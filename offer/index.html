What the steward runs

An outline, not a proposal. These are the parts of community web work that are hardest to staff with volunteers — so they are the parts worth taking on.

The workWhat it means in practice
The website, maintained automaticallyNot a volunteer remembering to update a page. Hours, festivals and class times stay current on their own, driven from one file.
A GitHub repository the community ownsBuilt and handed over. No subscription, no vendor, no login. It can be carried to any host, with or without the person who built it.
A record that can be checkedEvery fact traced to its source. Corrections dated and appended, never silently overwritten.
Whatever is useful after thatFestival dates that drop into a phone calendar, class sign-ups, a newsletter archive, a youth education section.
The order matters. Build the repository first and hand it over. Find uses for it second. A surface that already exists and already works is a far easier thing to extend than a plan for one.

What this does not ask for

  • No budget. GitHub Pages serves the surface free and the content is plain text.
  • No authority. This is a community mirror; the temple's own site governs.
  • No commitment. If it is unwelcome it comes down the same day it is asked for.
